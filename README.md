# payments
A personal learning project. I'm exploring how card payment APIs are designed and how
they fit together, and gathering ideas for how large language models could help me build
and understand software in this space.

## What this is

- **Learning scheme API ecosystem.** I'm working through scheme Developer Platform
  documentation and sandbox to understand how the APIs are structured: authentication
  (two-way TLS, API keys), request and response shapes, error handling, and how products
  such as account validation, push payments, foreign exchange rates and tokenization relate
  to one another.
- **Notes and small experiments**, kept here as I go.

## What this is not

- Not a commercial product, and not built for or on behalf of any employer or client.
- Not connected to any live payment network. 
- Not affiliated with or endorsed by any payments scheme or network
